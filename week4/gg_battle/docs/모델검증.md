# 예측 모델 검증

> 상위 문서: [README.md](../README.md) · 게임 쪽은 [게임설계.md](게임설계.md)

## 구조 — 2단 구조

```
[행동 7종] kill·cs·jungle·tower·ward·wardkill·firstBlood
     │  1단계: LinearRegression × 2   (R² 골드 0.948 / 경험 0.851)
     ▼
[goldDiff, expDiff] + [나머지 피처 9종]
     │  2단계: 미러 증강 → StandardScaler → LogisticRegression
     │          학습 후 계수를 **원단위로 역변환** (raw 계수 보존)
     ▼
P(승) = sigmoid(Σ βf · Δf)
```

**두 단계는 서로의 출력으로 학습하지 않는다.** 둘 다 원본 9,879경기의 *관측값*으로 따로 적합한다.
연결되는 건 게임이 돌아갈 때뿐이다 — 사람이 `kill`을 치면 1단계가 그걸 골드·경험 증분으로 바꾸고,
2단계가 그 상태를 승률로 바꾼다. 그래서 **학습 단계에는 오차 전파가 없다.**

2단계의 `killDiff` 계수는 `goldDiff`를 **같은 회귀에 넣고** 추정한 값이라 **골드를 뺀 직접효과**다.
골드 경로는 간접효과이고, 게임에서 체감하는 것은 **직접 + 간접 = 총효과**다. 이중계산이 아니라
**매개(mediation) 분해**다.

## 1단계는 왜 LinearRegression인가

행동 7종 → 골드·경험 변환기. CV R² (5-fold, 전체 9,879경기):

| 모델 | 골드 R² | 경험 R² | 환율이 상태와 무관하게 고정되는가 |
|---|---|---|---|
| **LinearRegression (채택)** | **0.9476** | **0.8506** | 예 |
| Ridge(α=1) | 0.9476 | 0.8506 | 예 |
| Ridge(α=100) | 0.9473 | 0.8506 | 예 |
| Huber (이상치 강건) | 0.9475 | 0.8505 | 예 |
| HistGB (비선형) | 0.9441 | 0.8434 | **아니오** |

정규화는 소수점 4자리까지 차이가 없다 — 피처 7개에 표본 9,879개라 과적합 여지가 없다.
**비선형은 성능도 낮고, 구조적으로 쓸 수 없다**: 게임의 보상표는 "킬 1회 = +431골드"처럼
**상태와 무관한 고정 환율**이어야 하는데, 트리는 상태마다 다른 값을 준다.
2단계에서 로지스틱을 택한 것과 **같은 논리가 독립적으로 성립**한다.

### 환율 계수의 신뢰구간 — 이 값이 곧 게임 보상표다

부트스트랩 1,000회로 1단계 골드 계수의 불확실성을 쟀다.

| 행동 | 골드 환율 | 95% CI | 변동폭 / 값 | 게임에서 |
|---|---|---|---|---|
| `killDiff` | 431.5 | [428.3, 434.9] | **1.5%** | 그대로 쓴다 |
| `csDiff` | 20.9 | [20.5, 21.4] | 4.1% | 그대로 쓴다 |
| `jungleDiff` | 21.9 | [21.1, 22.7] | 7.3% | 그대로 쓴다 |
| `towerDiff` | 1,071.2 | [1,030.3, 1,115.0] | 7.9% | 그대로 쓴다 |
| `firstBlood` | 86.6 | [75.1, 98.0] | 26.5% | 그대로 쓴다 (실제 롤 +100골드와 정합) |
| `wardKillDiff` | 8.9 | [5.4, 12.5] | **80.4%** | **데이터로 쓸 수 없다** |
| `wardDiff` | 0.8 | [0.3, 1.2] | **122.7%** | **데이터로 쓸 수 없다** |

**`ward`/`wardkill`만 신뢰구간이 자기 값만큼 넓다.** 이 둘을 데이터가 아닌 롤 메커니즘으로
설계한 것은 임의 판단이 아니라 **측정 결과에 따른 결정**이다
(→ [게임설계.md](게임설계.md)의 "유틸리티" 절). 나머지 5개는 변동폭이 8% 이내라 환율로 쓸 수 있다.

### 1단계 → 2단계 오차 전파 — R² 0.948은 승률 몇 %p인가

학습에는 전파가 없지만 **추론에는 있다.** 게임은 관측 골드를 모르고
`행동 → 1단계 → 2단계`가 유일한 경로이므로, 이 추상화가 얼마를 잃는지 재야 한다.
전체 9,879경기에서 **관측 골드·경험으로 낸 승률**과 **행동 7종만으로 1단계가 추정한 값으로 낸 승률**을 비교했다.

| 단계 | 값 |
|---|---|
| 1단계 적합 오차 (골드) | RMSE 561 · MAE 442 — 관측 표준편차 2,453의 **23%** |
| 1단계 적합 오차 (경험) | RMSE 742 · MAE 590 — 관측 표준편차 1,920의 **39%** |
| **승률 차이 \|Δ\|** | 중앙값 **3.90%p** · 평균 5.14%p · 95분위 14.05%p · 최대 32.6%p |
| **편향** | **+0.001%p** — OLS라 계통 오차가 없다 |
| \|Δ\| ≤ 5%p | 59.4% · (≤10%p 85.9%) |

**편향이 0이라는 게 핵심이다.** 승률이 한쪽으로 치우치지 않는다. 대신 **분산이 남는다** —
7개 행동이 골드차를 완전히 설명하지 못하기 때문이다(설명 못 한 23%가 승률 5%p 수준의 산포가 된다).

게임에는 `gold`·`level` 명령이 **따로** 있어서 이 경로를 우회할 수 있지만,
**"행동 → 승률" 환율이 개별 상태에서는 ±5%p 수준으로 흔들린다**는 사실은 남는다.
축 캡(±6,585골드) 안에서도 동일하다(평균 5.18%p).

> 이것이 **2단 구조의 비용**이다. 1단계를 없애면(= 행동을 직접 2단계에 넣으면) 이 오차는
> 사라지지만, 그러면 "킬 1회 = 431골드" 같은 **환율이 나오지 않아 게임 설계가 불가능**하다.
> 비용을 알고 치른 것이지 모르고 넘어간 것이 아니다.

모델당 1.5초 예산만큼 반복한 평균(최대 2,000회), `predict_proba(1행 ndarray)`,
`torch.set_num_threads(1)`. 지연시간은 분할 방식과 무관하므로 위 AUC와 그대로 붙는다.

### 결정적 증거: `gblinear` vs 트리

**같은 XGBoost인데 부스터만 바꾸면:**
```
gblinear(선형)  AUC 0.8109   ← 로지스틱과 소수점 4자리까지 동일
트리(기본)       AUC 0.7612   (−0.0497)
```
알고리즘 문제가 아니라 **데이터가 선형**이라는 뜻이다. 그리고 비선형을 넣을수록 나빠진다:
```
교호작용 추가   −0.0033      신경망 은닉층   −0.0021 ~ −0.0035
2차항 추가     −0.0024      깊은 트리       −0.0497
```

### LDA가 AUC 0.0003 높다 — 그래도 로지스틱인 이유

표에서 로지스틱보다 위에 있는 유일한 모델이라 따로 비교했다
(별도 측정: 미러 증강 없이 단일 테스트 집합, `stratify` 미사용 분할 — 절대값은 위 표와 다르다).

| 모델 | AUC | Brier | **ECE** | **캘리브레이션 기울기** |
|---|---|---|---|---|
| 로지스틱 | 0.8133 | 0.1764 | **2.10%** | **1.0362** |
| LDA | 0.8139 | 0.1762 | 2.18% | 1.0601 |

**변별력은 LDA가 근소하게 낫고, 캘리브레이션은 로지스틱이 낫다**(기울기가 1.0에 더 가깝고 ECE도 낮다).
차이는 전부 셋째 자리이므로 실질적으로 동률이다. 로지스틱을 택한 이유는 둘:

1. **승률을 %로 보여주는 앱**이라 변별력보다 캘리브레이션이 중요하다.
2. 로지스틱은 **로그오즈를 직접 모수화**하므로 계수가 곧 게임 환율이 된다. LDA 계수는
   **가우시안 생성모형 가정**에서 나오는데, `firstBlood`가 ±1 이진값이라 그 가정을 위반한다.

### 성능 외의 채택 이유 4가지

| | 로지스틱 | 트리 / 신경망 |
|---|---|---|
| 성능 | 최상위 (0.8109) | 같거나 나쁨 |
| 추론 속도 | **0.72ms** | RF 112.8ms · ET 115.1ms — **게임 불가**<br>XGB·LGBM은 0.9~1.8ms로 **속도는 문제없다** |
| 설명 | `reasons` 기여도가 **수학적으로 정확히 분해** | SHAP 필요, 근사값 |
| **게임 엔진** | **raw 계수가 곧 환율** (드래곤 = 799골드) | **추출 불가** |
| 캘리브레이션 | 기울기 0.974, 보정 불필요 | 별도 보정 필요 |

**속도는 RandomForest·ExtraTrees에서만 결정적이다.** XGBoost·LightGBM은 1~2ms라
`SEC`(타당 처리시간 0.3초)의 1% 미만이고, 게임에는 아무 지장이 없다. **그러니 이 둘을 기각한
이유는 속도가 아니다** — 성능이 같거나 낮은데(gblinear는 소수점 4자리까지 동률, 트리는 −0.05)
**raw 계수를 뽑을 수 없다는 것**이 이유다.

**네 번째가 결정적이다.** 이 프로젝트의 쿨타임·캡·보상·N타 분할이 전부 선형 계수에서 유도됐다.
트리로 바꾸면 "드래곤 1개 = 799골드" 같은 환율을 뽑을 수 없어 게임 설계 자체가 성립하지 않는다.

## AUC 밖의 증거 4가지 — 게임에 쓰는 모델에는 다른 것이 중요하다

AUC 차이는 0.002~0.05로 작다. 그래서 **AUC로는 결론이 안 난다.** 아래 네 지표에서는 차이가 크다.
전부 같은 분할(학습 7,409 / 테스트 2,470, `random_state=42`)의 테스트 집합에서 측정했다.

### ① 단조성 — "좋은 행동을 했는데 승률이 떨어지지 않는가"

테스트 2,470개 상태 각각에서 `gold` 1회(+100골드)를 쳤을 때 승률이 어떻게 변했나.

| 모델 | 상승 | **무변화** | **하락** | 평균 ΔP |
|---|---|---|---|---|
| **로지스틱 (채택)** | **100.0%** | **0.0%** | **0.0%** | +0.840%p |
| XGBoost 얕게·강정규화 | 29.9% | **68.0%** | 2.1% | +0.657%p |
| LightGBM 얕게·강정규화 | 30.7% | **67.7%** | 1.6% | +0.668%p |
| MLP(64,32) sklearn | 81.4% | 0.0% | **18.5%** | +0.974%p |
| RandomForest(500) | 53.7% | 7.5% | **38.8%** | +0.575%p |

드래곤 +1로 바꿔도 같다 — RF는 **17.2%**, MLP는 **33.8%**의 상태에서 **드래곤을 먹었는데 승률이 내려간다.**

**게임에서 이건 치명적이다.** RandomForest를 쓰면 38.8%의 상황에서 골드를 벌수록 게이지가 내려가고,
XGBoost·LightGBM은 68%의 상황에서 **쳐도 아무 일이 일어나지 않는다**(계단함수라 분기점을 안 넘으면 ΔP = 0).
선형 모델은 **구조적으로** 위반률이 0이다 — 계수 부호가 상태와 무관하게 같기 때문이다.

### ② 외삽 — 캡 근처에서도 반응하는가

게임은 캡까지 치면 관측 범위 경계(골드차 ±11,000)에 닿는다. 그 밖에서 승률(다른 피처 0 고정):

| 모델 | −15,000 | −11,000 | 0 | +11,000 | +15,000 | 경계 밖 반응 |
|---|---|---|---|---|---|---|
| **로지스틱 (채택)** | 0.1% | 0.6% | 50.0% | 99.4% | 99.9% | **+0.48%p** |
| XGBoost 얕게·강정규화 | 11.7% | 11.7% | 45.8% | 84.8% | 84.8% | +0.00%p |
| LightGBM 얕게·강정규화 | 12.6% | 12.6% | 45.3% | 86.9% | 86.9% | +0.00%p |
| MLP(64,32) sklearn | 0.0% | 0.0% | 68.4% | 100.0% | 100.0% | +0.00%p |
| RandomForest(500) | 22.0% | 22.0% | 48.6% | 66.8% | 66.8% | +0.00%p |

트리 계열은 경계 밖에서 **정확히 평평**하다(계단함수의 마지막 칸). 더 심각한 건 **포화 수준**이다 —
RandomForest는 골드차 +11,000에서도 **66.8%**밖에 못 올라간다. 압도적으로 이기고 있는 상태를
"66.8%"라고 말하는 승률 게이지는 쓸 수 없다. 선형은 0.1% ~ 99.9%로 전 구간을 쓴다.

### ③ 재현성 — 시드를 바꿔도 같은 모델이 나오는가

`random_state`만 5개(0·1·42·123·2024) 바꿔 재학습했을 때 테스트 AUC의 흔들림:

| 모델 | 표준편차 | 최대−최소 |
|---|---|---|
| **로지스틱 (채택)** | **0.000000** | **0.000000** |
| LightGBM 얕게·강정규화 | 0.000284 | 0.000709 |
| XGBoost 얕게·강정규화 | 0.000693 | 0.001858 |
| RandomForest(500) | 0.000771 | 0.002276 |
| MLP(64,32) sklearn | 0.005959 | 0.016345 |

로지스틱 회귀의 손실함수는 **볼록**이라 전역 최적해가 유일하다. 시드를 바꿔도 **소수점 아래 전부 동일**하다.
게임 밸런스가 계수에서 유도되므로, **재학습할 때마다 밸런스가 바뀌면 안 된다.**

### ④ 쌍체 부트스트랩 — AUC 차이가 통계적으로 유의한가

같은 테스트 집합을 2,000회 재추출해 **쌍으로** 비교했다(두 모델이 같은 표본을 본다).

|---|---|---|---|---|
| XGBoost 얕게·강정규화 | +0.0048 | [+0.0010, +0.0087] | 0.017 | **채택 모델 우위** |
| LightGBM 얕게·강정규화 | +0.0036 | [−0.0002, +0.0073] | 0.066 | 차이 없음 |
| RandomForest(500) | +0.0146 | [+0.0085, +0.0207] | <0.001 | **채택 모델 우위** |

**LightGBM과는 통계적으로 차이가 없다**(CI가 0을 포함). 이것도 그대로 적는다 — 성능만 보면
LightGBM은 대등한 선택지다. 기각 이유는 ①②③과 계수 추출 불가이지 AUC가 아니다.

## 평가 지표 — 4층 구조

승률을 **%로 표시**하는 앱이므로 AUC만으로는 부족하다. 캘리브레이션까지 봐야 한다.

| 층 | 지표 | 값 | 읽는 법 |
|---|---|---|---|
| **변별력** | AUC-ROC | **0.8109** [0.7936, 0.8274] | 이긴 쪽에 더 높은 확률을 줄 확률 (부트스트랩 2000회 CI) |
| | AUC-PR | 0.8117 (기준 0.4992) | 불균형에서 AUC보다 정직 |
| | Gini | 0.6219 | 2·AUC−1 |
| **캘리브레이션** | **Brier** | **0.1775** | 확률 예측의 MSE |
| | ├ 신뢰도 | **0.00071** | **0에 가까울수록 정직** ← 핵심 |
| | ├ 해상도 | 0.07272 | 클수록 변별력 |
| | └ 불확실성 | 0.25000 | 데이터 고유값, 줄일 수 없음 |
| | ECE / MCE | 2.25%p / 6.07%p | 평균 / 최대 캘리브레이션 오차 |
| | 캘리브레이션 기울기 | **0.9739** | 1.0이 완벽. <1이면 과신 |
| | 캘리브레이션 절편 | −0.0189 | 0이 완벽 |
| | LogLoss | 0.5269 | 틀린 확신에 강한 벌점 |
| **숙련도** | **Brier Skill Score** | **+0.2898** | 기준선(항상 50%) 대비 29% 개선 |
| | LogLoss Skill | +0.2398 | |
| **임계값** | MCC | 0.4462 | 불균형에 강한 상관계수 |
| | 균형 정확도 / F1 | 72.3% / 0.7237 | |
| **예리함** | 예측 표준편차 | 0.2747 | 박빙 20.4% · 극단(0~10%,90~100%) 15.5% |

**Brier 분해가 가장 유용하다.** `Brier = 신뢰도 − 해상도 + 불확실성`
(검산: 0.00071 − 0.07272 + 0.25000 = 0.17799)
신뢰도 0.00071은 거의 완벽하고, **남은 오차는 전부 불확실성(0.25)에서 온다 — 모델이 아니라 데이터 한계**다.

## 피처 중요도 · 학습곡선

```
goldDiff +0.227 ≫ expDiff +0.037 > dragDiff +0.012 > killDiff +0.003
> csDiff +0.002 > towerDiff +0.001 > firstBlood·heraldDiff·jungleDiff·wardKillDiff·wardDiff ≈ 0
```

`ward`/`wardkill`의 기여는 **+0.00001** — 게임에서 유틸리티로 보완한 이유가 여기 있다.

### 학습곡선 — 데이터를 더 모아도 소용없다

| 학습 표본 | 학습 AUC | 검증 AUC | 격차 |
|---|---|---|---|
| 790 | 0.8292 | 0.8069 | +0.0223 |
| 3,635 | 0.8127 | 0.8101 | +0.0026 |
| 7,903 | 0.8117 | 0.8109 | **+0.0008** |

**과적합 없음**(격차 0.0008), 검증 AUC는 2,200표본부터 평평하다.


### 발견한 문제와 수정 — 미러 증강

게임이 만드는 상태 2,000판을 학습 분포와 대조했더니 **`towerDiff`가 13.9%에서 분포 밖**이었다.
데이터 관측 범위가 **−2~+4로 비대칭**인데(블루가 4개, 레드는 2개까지만 관측된 샘플링 노이즈)
게임은 양쪽 대칭으로 ±4를 허용하기 때문이다.

**블루/레드 라벨은 임의**이므로, 모든 차이값의 부호와 정답을 뒤집은 사본을 학습에 더했다.
AUC는 그대로(0.8109)인데 세 가지가 공짜로 해결됐다:

| | 증강 전 | 증강 후 |
|---|---|---|
| 절편 | +0.0169 (블루 진영 프리미엄) | **정확히 0** → 1대1에서 절편 제외가 유도 결과가 됨 |
| P(나)+P(상대) | 평균 오차 0.42%p | **정확히 100%** |
| `towerDiff` 지원 | −2 ~ +4 | **±4** → 분포 밖 13.9% → **0.0%** |

> 게임이 승률 게이지를 보여주는 용도에는 정확히 맞는 성질이다.

## 성능 한계는 모델이 아니라 데이터다 — 증거 4개
