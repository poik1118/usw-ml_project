## 2. 잘한 점

골드를 통제하면 타워·킬·CS 계수가 음수로 뒤집히는 현상을 숨기지 않고 단독 상관과 통제 비교 화면으로 데이터에서 증명하겠다는 설계는 이 과목의 "구현 이해도" 항목에서 가장 좋은 답이 됩니다. 응답 형식(score, level, reasons)을 고정해 3단계에서 화면을 고치지 않게 한 것, JupyterHub 프록시 제약을 리스크로 잡고 봇 대결로 대체하는 대안도 정확합니다.

## 3. 4주차 체크포인트 1(0:40) 전에 고칠 것

1. 시연 시나리오의 순서를 정하세요. 1대1 대결은 두 기기가 같은 계정으로 로그인해야 해서 교실 네트워크에서 가장 먼저 깨질 기능입니다. 시연은 승률 분해 → 데이터 근거 → 시뮬레이터 단독 모드 순으로 1분 30초를 채우고, 실제 대결은 Q&A에서 보여 주거나 백업 영상으로 두세요.
2. 1단계부터 로지스틱 회귀를 쓴 것은 괜찮지만, 2단계는 "트리 계열과 비교"만으로는 리더보드에서 할 일이 적습니다. 골드 통제 조건에서 계수가 뒤집히는 피처들을 상호작용 항이나 비율 피처(골드당 킬 등)로 다시 설계하는 것을 2단계 계획으로 적어 두세요. 이미 알고 있는 현상이 곧 피처 설계의 재료입니다.
3. 제출한 PDF는 글자 사이 공백이 모두 빠져 텍스트로 읽히지 않습니다. 기획서와 SPEC.md는 md로 제출하세요. 프로젝트 폴더가 ~/work/week4/gg_battle인데 실습 폴더 밑이 아니라 ~/work 바로 아래에 두는 것이 안전합니다.

## 4. 2·3단계 연결 메모

분류 문제이며 타깃이 균형이라 정확도와 AUC 모두 써도 됩니다. 현재 AUC 0.81은 10분 시점 데이터의 알려진 상한 근처이므로 2단계에서 큰 폭의 향상은 기대하기 어렵습니다. 리더보드보다는 "선형 모델의 설명 가능성과 트리 모델의 성능 차이가 얼마나 되는가"를 보고서로 정리하는 것이 본인 서비스의 가치(항별 기여도 분해)와 맞습니다. 3단계 API는 이미 설계한 형식 그대로 가면 됩니다.
